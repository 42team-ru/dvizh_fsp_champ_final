# Движ — платформа совместных спортивных активностей

Финал Чемпионата России по продуктовому программированию, кейс Столото.

Адаптивное веб-приложение помогает перейти от «хочу заниматься, но не с кем» к конкретной встрече: кто собирается, где, когда и как присоединиться. Встречу может создать человек или допущенный клуб. Запись свободная или по заявке, условия уточняются в обсуждении под событием. Администратор допускает клубы и снимает некорректные события.

Модель общая для всех видов спорта: футбол, шахматы, бег, зарядка во дворе и любой свой вид («Петанк», «Сапсёрфинг») обрабатываются одинаково. Новый вид спорта создаётся из формы события и не требует правки кода.

## Запуск

Нужен только Docker:

```bash
docker compose up --build
```

Приложение откроется на http://localhost:8080, Swagger — на `/swagger-ui.html`. Первая сборка занимает 2–3 минуты. Демо-режим включён, данные создаются при первом старте. Полный сброс данных: `docker compose down -v`.

Для разработки:

```bash
make dev     # Postgres :5440 и S3/MinIO :9440, один раз
make back    # бэкенд :8080
make front   # фронт :5173, /api проксируется на бэкенд
cd backend && ./gradlew test          # быстрые тесты на H2
cd backend && ./gradlew postgresTest  # проверка миграций на настоящем Postgres (нужен Docker)
```

Без make: `node scripts/dev.mjs [back|front]`, работает и на Windows.

## Демо-аккаунты

Пароль у всех `demo-password-1`. На странице входа есть кнопки быстрого входа: они подставляют логин и пароль в обычную форму.

| Логин | Роль | Для чего |
|---|---|---|
| `anna` | пользователь | ищет встречи, записывается, задаёт вопросы |
| `petr` | пользователь-организатор | автор события «по заявке», принимает и отклоняет заявки |
| `vika` | пользователь-организатор | весь гардероб бобра: заработала монеты на своих встречах и скупила магазин |
| `ladya` | клуб «Ладья», допущен | публикует события сразу, есть публичная страница |
| `enisey` | клуб «Енисей», заявка на проверке | публиковать нельзя, видит статус заявки |
| `admin` | администратор | допускает клубы, снимает события |

Без кнопок можно войти ещё под `olga` (пенсионерка, зарядка во дворе) и пользователями массовки, например `dmitry` или `elena`.

## Как проверить шесть сценариев

1. **Создание события пользователем.** Войти как `anna` → «Создать». Указать название, вид спорта (из подсказок или свой, например «Кёрлинг» → «Добавить как новый вид»), дату и время, адрес (из подсказок или кликом по карте), условия, режим записи → «Опубликовать». Затем войти как `petr` → «Лента» → поиск по названию → открыть событие.
2. **Допуск организации.** На странице регистрации выбрать «Я представляю клуб». После регистрации откроется анкета: название, описание, виды спорта, контакты → «Отправить на проверку». Статус «на проверке» виден в кабинете, кнопка «Создать» неактивна с пояснением. Решение администратора см. в разделе «Известные ограничения». После одобрения клуб видит статус «допущен», публикует событие без согласования, а пользователь открывает страницу клуба по ссылке «Страница организации» из карточки события. Готовые клубы для проверки: «Ладья» (допущен) и «Енисей» (на проверке).
3. **Свободная запись.** Войти как `anna` → открыть событие со свободной записью → «Записаться». Сразу видно «Вы записаны» и приватные детали. Организатор: «Кабинет» → событие → «Заявки» → «Приняты».
4. **Запись по заявке.** Войти как `anna` → открыть турнир «Ладьи» по шахматам → «Подать заявку». Видно «Ожидает решения». Войти как `ladya` → «Кабинет» → событие (или кнопка «Управлять» в карточке) → «Принять» или «Отклонить» с причиной. Пользователь видит «Вы записаны» или «Заявка отклонена» с причиной. Для второй ветки нужен ещё один пользователь, например `petr`.
5. **Уточнение условий.** Под событием в блоке «Обсуждение» задать вопрос. Организатор отвечает кнопкой «Ответить»: его сообщение отмечено меткой «Организатор» и цитирует вопрос.
6. **Снятие с публикации.** Администратор снимает или удаляет событие с причиной. Событие пропадает из ленты, поиска и карты. По прямой ссылке открывается красная плашка «Снято с публикации» с причиной, кнопки записи нет, API записи отвечает 409. В демо уже есть снятое событие с записанным участником.

## Правила доступа и модерации

Все правила проверяются на сервере. Скрытая кнопка в интерфейсе — только подсказка.

- **Роли:** `USER`, `ORG`, `ADMIN`. Организатор события — не отдельная роль: это автор (`USER` или `ORG`) или его соорганизатор.
- **Клуб** публикует события только при статусе «допущен». Сохранение анкеты и есть заявка: первая анкета и правка после отказа или возврата на доработку уходят на проверку. Публичная страница клуба открыта только после допуска. Если допуск отозван, события клуба пропадают из ленты.
- **Запись:** при свободной записи участник подтверждается сразу, а если мест нет — встаёт в лист ожидания. При записи по заявке статус «Ожидает решения» до решения организатора. Записаться нельзя на снятое, удалённое или уже начавшееся событие, на своё событие, а также с аккаунта клуба или администратора. Последнее место защищено блокировкой строки события.
- **Решения по заявкам** принимает только организатор (автор или соорганизатор). Администратор их не рассматривает и не создаёт события.
- **Приватные детали** (точное место, ссылка на чат или трансляцию) видят только подтверждённые участники и организатор.
- **Обсуждение:** комментировать может любой вошедший пользователь, в том числе не записанный. Администратор удаляет отдельное сообщение прямо в обсуждении события с причиной; в потоке остаётся заглушка.
- **Модерация текстов:** сообщения, мероприятия, профили и анкеты клубов с матом не сохраняются (словарь ловит и замаскированный мат). Опубликованное в фоне проверяет нейросеть: сомнительное попадает в очередь администратора («Модерация»), сообщение в обсуждении скрывается само, если серьёзное нарушение (угроза, травля, ненависть, непристойность, реклама) видят минимум два источника из трёх: словарь, классификатор токсичности и нейросеть, а админ может вернуть ([docs/moderation.md](docs/moderation.md)).
- Права на действия считает один класс `EventAccessPolicy`. Карточка события приходит с блоком `viewer`, и фронт рисует кнопки только по нему.

## Что имитировано

- **Вход:** логин и пароль настоящие (JWT в HttpOnly cookie), но подтверждения почты, восстановления пароля и OAuth нет. Демо-аккаунты подставляются кнопками.
- **Проверка клуба:** это решение администратора, а не юридическая экспертиза. Документы можно приложить файлом, интеграции с реестрами нет.
- **Демо-данные** создаются через те же сервисы, что и REST API. Единственная условность — время: прошедшие встречи создаются будущими, а затем их метки времени переносятся в прошлое.
- **Уведомления** живут только внутри приложения (раздел «Активность»), почты и мессенджеров нет.

## Известные ограничения

- **Экраны администратора не реализованы.** Бэкенд готов полностью: `/api/admin/*` — список и поиск клубов и событий, одобрение, отклонение и возврат на доработку с причиной, снятие, удаление и восстановление событий, скрытие комментариев. Сейчас эти действия проверяются через Swagger (`/swagger-ui.html`) под входом `admin`.
- Адрес очной встречи выбирается из подсказок 2ГИС или кликом по карте: координаты нужны для карты и поиска «рядом». Без доступа к API 2ГИС создать очное событие нельзя, онлайн-формат работает.
- Карта и геопоиск используют PostGIS. Образ `postgis/postgis` собирается только под amd64.
- Модели модерации маленькие (нейросеть 0.8B и классификатор rubert-tiny): возможны ложные флаги и пропуски, поэтому само скрывается только то, что признали серьёзным минимум два источника из трёх, а решение всегда за администратором. При первом запуске модели (~0,5 ГБ) качаются из интернета, а проверка демо-данных идёт в фоне. Без моделей (`MODERATION_LLM_ENABLED=false`, `MODERATION_CLASSIFIER_ENABLED=false`) работает только словарь.

## Реализованные доп. функции

- Устанавливаемое PWA: иконка на домашнем экране, ярлыки, офлайн-оболочка и уведомление об обновлении ([проверка](docs/frontend.md)).
- Каталог «Организации», подписки на анонсы новых встреч и публичная страница клуба со статистикой, архивом, фото, расписанием и наградами ([docs/organizations.md](docs/organizations.md)).

- Лист ожидания, лимит мест, отмена записи, повторяющиеся встречи (RRULE) с отметкой «приду» на каждое занятие, перенос и отмена занятий.
- Кворум «состоится, если наберём N» и подтверждение организатором.
- Соорганизаторы события.
- Интерактивная карта с кластерами и поиск «рядом».
- Персональная подборка «Подобрали для тебя» с объяснением причин и кнопкой «Не интересно», похожие встречи ([docs/recommendations.md](docs/recommendations.md)).
- Онбординг: интересы, уровень, удобное время и радиус.
- «Поделиться» встречей и паспортом: превью и скачивание PNG 1080×1350 / 1080×1920 с QR, копирование ссылки и отправка в Telegram, ВКонтакте, WhatsApp. Изображение собирается в браузере с локальными шрифтами. Календарь `.ics` для каждой встречи.
- Мягкая геймификация: бобр-питомец, монеты за посещения, достижения, «Организация месяца» ([docs/economy.md](docs/economy.md), [docs/beaver-pet.md](docs/beaver-pet.md)).
- «Кто идёт» на странице встречи: компания бобров участников в своих нарядах на общей поляне, с переходами в профили.
- Альбом фото по прошедшим занятиям в профиле.
- Блог (`/blog`): гайды и посты с тренировок с фото из альбома встречи, Markdown-редактор как в Telegram, лайки, комментарии с ответами и виджет «Наши тренировки» в конце поста. После встречи бобр пользователя предлагает «Написать пост»: в ленте блога, на странице встречи и в «Активности». Блог есть и в профиле, и на странице клуба.
- Фото мероприятия прямо при создании; у каждого фото точка фокуса, по которой обрезаются превью в ленте, на главной и в билете. У стоковых иллюстраций видов спорта точка стоит на голове персонажа.
- Админ удаляет отдельное сообщение прямо в обсуждении события с причиной; в потоке остаётся заглушка. Удалённое сообщение можно вернуть.
- Автомодерация текстов тремя источниками: словарь (мат с защитой от маскировки, угрозы, непристойности, реклама заработка), классификатор токсичности rubert-tiny-toxicity и локальная нейросеть Qwen3.5-0.8B (llama.cpp, CPU). Сообщение скрывается само, если серьёзное нарушение видят двое из трёх; остальное и сообщения не по теме — в очередь «Модерация» ([docs/moderation.md](docs/moderation.md)).

## Стек и структура

- **Бэкенд:** Java 25, Spring Boot 4.1 (Gradle Kotlin DSL), PostgreSQL 18 + PostGIS, Flyway, Spring Security (JWT), springdoc, MapStruct.
- **Фронт:** React Router 7 (SPA), Vite, Tailwind 4, shadcn/ui, TanStack Query и Form, zod, клиент API генерирует Orval из OpenAPI.
- **Инфраструктура:** Docker, Caddy, GitHub Actions → GHCR → VPS. Файлы хранятся в S3 (MinIO).

```
backend/   com.hackathon.app: rest → service → repository → domain (entity, dto, mapper, enums), demo — демо-данные
frontend/  src: app (маршруты), pages, widgets, features, entity, shared (ui, api — сгенерированный клиент)
deploy/    docker-compose и Caddy для сервера
docs/      подробная документация
```

Внешние сервисы: API 2ГИС (карта и геокодер, бесплатный ключ). Платных лицензий проверка не требует.

## Уведомления

Во вкладке «Активность» — входящие и настройки внешних каналов: Telegram по одноразовой ссылке,
Email и MAX с подключением контакта в демо-режиме (без реальных отправок). Категории сохраняются автоматически.
На главной «Бублик подсказывает», когда выходить на ближайшую встречу: пешком, на автобусе или на машине
по маршрутам 2ГИС (с учётом, ходит ли транспорт), и ставит личное напоминание.
Контракт и настройка Telegram: [docs/notifications.md](docs/notifications.md).
