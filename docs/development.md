# Локальная разработка

Нужны: Java 25, Node (+ yarn), Docker.

## Запуск
```bash
make dev     # Postgres с PostGIS (5440) и MinIO/S3 (9440, консоль http://localhost:9441, app / app-secret-dev) в докере; один раз, дальше работают сами
make back    # бэкенд  http://localhost:8080 (swagger: /swagger-ui.html), в своём терминале
make front   # фронт    http://localhost:5173 (/api проксируется на бэк), в своём терминале
make dev-down  # остановить БД и MinIO разработки (данные сохраняются)
```
Без make: `node scripts/dev.mjs [back|front]` (работает и на Windows).
Бэкенд и фронт запускаются **отдельно**, чтобы каждый можно было быстро перезапустить: Ctrl+C и снова `make back`.
Бэкенд можно запускать и из IDE (класс `TestAppApplication` или `AppApplication`).

## Всё одной командой (как у жюри)
```bash
docker compose up --build      # http://localhost:8080, нужен только Docker
```
Всё собирается из исходников (`backend/Dockerfile`, `frontend/Dockerfile`), миграции применяются при старте. Первая сборка ~2–3 минуты.
Порт меняется так: `PORT=80 docker compose up --build`.

## Демо-режим
В корневом `docker-compose.yml` включён (`DEMO_MODE=true`): при старте создаются аккаунты `admin` (админ), `anna`, `petr`, `olga`, клубы `ladya` и `enisey`, а также данные «живого проекта» — сотни пользователей в 12 городах, клубы, мероприятия, записи и обсуждения за полгода (`DemoBulkSeeder`) с записями (`DemoSeeder`; весь демо-код лежит в пакете `com.hackathon.app.demo` и вызывает сервисы как клиент, монеты и достижения получаются из настоящей обработки прошедших встреч), пароль `demo-password-1`, а на странице входа появляются кнопки для `anna`, `ladya`, `enisey` и `admin`, которые подставляют логин и пароль в форму (`petr`, `olga` и массовые пользователи — без кнопок, вход по логину). Пароль публичный, поэтому на сервере с реальными пользователями режим выключен (`DEMO_MODE=false` по умолчанию в `deploy/`). Включить на демо-сервере: [dev-faq.md](dev-faq.md#как-включить-или-выключить-демо-режим).

## Тесты
```bash
cd backend
./gradlew test           # быстрые, на H2, Docker не нужен
./gradlew postgresTest   # смоук на настоящем Postgres (Testcontainers, нужен Docker)
./gradlew check          # оба; так же гоняет CI
```

## Git-хуки
Включаются сами при `yarn install` или первой сборке Gradle (вручную: `make hooks`), нужен Node. Хуки проверяют сообщения коммитов и добавленный код на запрещённые слова и не пропускают мусорные файлы.
`make junk` — отчёт по мусору в git, `make clean` — удалить локальные артефакты сборки, `make scan` — отчёт по истории и коду.

## Файлы (S3)

Аватарки, логотипы и документы организаций, фото мероприятий хранятся в S3-бакете `app-files` (бэкенд создаёт его сам при старте), метаданные — в таблице `files`. Браузер получает файл только через бэкенд: `GET /api/files/{id}` с проверкой прав; MinIO наружу не открыт.

- Локально и на сервере — MinIO (`pgsty/minio`: официальные образы MinIO больше не публикуются, это сборка того же MinIO с закреплённым тегом). Можно подключить любой S3 через `S3_ENDPOINT`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`, `S3_BUCKET`, `S3_REGION`.
- `STORAGE_TYPE=memory` — файлы в памяти процесса, без MinIO (так работают тесты на H2).
- Лимиты: изображения JPG/PNG/WebP до 5 МБ, документы PDF/JPG/PNG до 10 МБ; формат определяется по содержимому, а не по расширению. Фото у мероприятия — до 6, документов у организации — до 10.
