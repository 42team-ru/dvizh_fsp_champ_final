# Рекомендации: подборка мероприятий и клубов

Персональная подборка «Вам подойдёт», «Клубы для вас», «Похожие встречи» и кнопка «Не интересно».
Код: `RecommendationService` (сценарии), `RecommendationSignals` (сбор сигналов), `EventScorer` (формулы),
`DiversityRanker` (порядок с разнообразием), `RecommendationRepository` (запросы), `util/RecommendationMath`, `util/Geo`.
Тесты: `RecommendationsE2ETest`.

## Почему так

- **Объяснимо.** Оценка — взвешенная сумма понятных признаков, каждый в [0, 1]. Поэтому у каждой карточки есть
  1–3 причины («Вы занимаетесь: футбол», «1,2 км от дома», «Идёт Анна — вы уже занимались вместе»), а
  `explain` показывает всю раскладку. Чёрный ящик (матричная факторизация, нейросеть) на таком объёме данных
  переобучится и ничего не объяснит.
- **Без обучения и кэшей.** Демо — сотни людей и мероприятий. Всё считается на каждый запрос из текущих данных:
  записался, скрыл, поменял интересы — подборка сразу другая. Один запрос на вид сигнала, без запросов на каждое
  мероприятие.
- **Нет данных — нет штрафа.** Признак, для которого у человека нет данных (нет точки, нет предпочтений), выключается,
  а сумма делится на веса только включённых признаков. Новичок без профиля не проигрывает из-за пустых полей.
- **Переносимо.** Только JPQL и Java, без PostGIS и pg_trgm: всё работает и на H2 в тестах.

## Подборка мероприятий

### Кандидаты
Опубликованные, видимые (организация одобрена) мероприятия с занятием в окне `[сейчас + 30 мин, сейчас + 30 дней]`,
до 500 ближайших. Не показываем: свои (автор или соорганизатор), уже записан (CONFIRMED / PENDING / WAITLISTED),
отклонённую заявку, скрытые мной, разовые без мест, очные дальше `3 × радиус`. Аккаунтам организаций и админу —
пусто: они не записываются.

### Признаки

| Признак | Формула | Вес |
|---|---|---|
| **SPORT** — интерес к виду | `max(p(u,s), 0.6 · maxₜ p(u,t)·sim(t,s))` | 0.30 |
| **DISTANCE** — расстояние | `2^(−(d/R)²)`: 1 рядом, 0.5 на радиусе; онлайн 0.6 | 0.15 |
| **LEVEL** — уровень | «Любой» 0.85, совпал 1, проще 0.6, сложнее 0.4, через ступень 0.05 | 0.12 |
| **TIME** — удобное время | `0.6·[день] + 0.4·[время суток]`, пополам с привычками | 0.12 |
| **SOCIAL** — идут знакомые | `1 − e^(−F/2)`, `F = Σ w(u,v)` по участникам | 0.08 |
| **ORGANIZER** — знакомый организатор | `max(ℓ(o), 0.5 · max ℓ(o')·J(o',o))` | 0.08 |
| **TRUST** — надёжность | `h / (h + 5)`, у организации +0.1 | 0.05 |
| **POPULARITY** | `1 − e^(−n/6)` | 0.04 |
| **QUORUM** — почти набрали | 1, если до кворума не хватает 1–3 человек | 0.03 |
| **URGENCY** — когда начнётся | 1 через 6–72 ч, ближе — меньше, дальше `e^(−(t−72)/168)` | 0.03 |

**Интерес к виду спорта `p(u,s)`.** Сырой вес `r(u,s)` — сумма сигналов с экспоненциальным затуханием
`2^(−Δt/45 дней)`: вид в профиле 3.0 (не затухает), посещённое занятие 1.0, проведённое мероприятие 1.0,
текущая запись 0.8, отклонённая заявка 0.5, своё сообщение в обсуждении 0.3, отменённая запись 0.2.
Нормируем на максимум: `p = r / max r`, любимый вид = 1.

**Похожесть видов `sim(s,t)`** — косинус по множествам занимающихся (профили + подтверждённые записи):
`|A∩B| / √(|A|·|B|)`, сжатый на малой выборке `· n/(n+5)`, где n — общие люди. Два человека, случайно
совпавших, не делают виды похожими; двадцать — делают. Так любителю футбола попадается мини-футбол с причиной
«Похоже на ваш интерес: футбол».

**Расстояние** — гаверсинус до точки отсчёта: `lat/lon` запроса (геолокация) → домашняя точка из предпочтений →
покоординатная медиана последних 10 мест, где человек занимался (медиана устойчива к одной поездке в другой город).
Радиус: запрос → предпочтения → 10 км.

**Время** — по местному времени занятия: пояс серии, иначе пояс ближайшего крупного города по координатам
(`Geo.zoneNear`), иначе `app.notifications.time-zone`. Утро 5–11, день 12–16, вечер — остальное; соседний отрезок
суток засчитывается наполовину. Привычка — гистограмма 7 дней × 3 отрезка по посещениям со сглаживанием Лапласа
`(n+1)/(max+1)`; учитывается от 3 посещений.

**Знакомые `w(u,v)`** — сколько прошедших занятий мы были вместе (разовые — обе записи подтверждены, серии — обе
отметки). **Организатор**: ключ — организация, у частного лица — автор; лояльность `ℓ = 1 − e^(−k/2)`, k — мои
посещения у него; похожие организаторы — Жаккар их аудиторий со сжатием `· n/(n+5)` («к ним ходят те же люди»).

### Итог
```
score = gate · penalty · Σ wᵢ·fᵢ / Σ wᵢ (по включённым)
gate    = 0.3, если LEVEL < 0.1 (новичку — профи), иначе 1
penalty = max(floor, sportFactor^k · Π (1 − similarStrength · sim(x, c) · decay(x)))
          k — скрытия «Не мой вид спорта» этого вида с тем же затуханием,
          Π — по скрытым встречам x, у которых sim(x, c) ≥ minSimilarity
sim     = 0.45·[вид: 1 тот же, иначе sim(t,s)] + 0.25·[тот же организатор]
        + 0.15·[тот же день недели и время суток] + 0.15·[ближе nearKm = 3 км]
```
Скрытая встреча («Не интересно») уходит из подборки, но остаётся в ленте и поиске. Похожие на неё опускаются
ниже, но не пропадают: `floor = 0.35` не даёт штрафу обнулить встречу. Все константы формулы (веса, порог причин,
доли «похожего», `levelGate`, параметры штрафа) — в `application.yml`, раздел `app.recommendations.scoring` и
`app.recommendations.dismiss`.
Причины — признаки с наибольшим вкладом `wᵢ·fᵢ / Σw` (не меньше 0.03), до трёх; если ни одна не прошла —
«Начнётся через …».

### Порядок: разнообразие и «Попробуйте новое»
Maximal Marginal Relevance: на каждую позицию берём кандидата с наибольшим
`λ·score − (1−λ)·max sim(e, уже выбранные)`, `λ = 0.75`, где `sim = 0.6·[тот же вид] + 0.3·[тот же организатор] +
0.1·[тот же день]`. Иначе вся первая страница — один клуб.
Каждая 5-я позиция — **discovery**: лучший по оценке без SPORT среди видов, с которыми человек не связан
(`discovery: true`, причина «Попробуйте новое: петанк»). Детерминированно — демо не прыгает. При холодном старте
слотов нет: там всё новое.

### Холодный старт
Нет интересов и истории → SPORT и ORGANIZER выключены, общий уровень — «Новичок»: встречи «Любой уровень» и
«Для новичков» поднимаются (причина «Подходит новичкам»), профи гасятся множителем. Работают расстояние, время,
надёжность, популярность.

## Похожие встречи (`events_similar`)
Похожесть на исходное мероприятие:
`0.45·sim видов + 0.15·уровень + 0.15·место (ядро 5 км) + 0.10·время (час суток ядром 3 ч + тот же день недели) +
0.15·общие участники (Жаккар со сжатием n/(n+3))`. Другие виды — только при `sim ≥ 0.3`. Если у человека есть профиль,
`× (0.7 + 0.3·личная оценка)`. Затем MMR. Контракт прежний: список `EventSummaryResponse`.

## Клубы для вас
Одобренные организации со встречами в ближайшие 30 дней (кроме своей):
- вид спорта (0.40): `Σ p'(s) / √|виды|` по видам анкеты и её встреч, `p'` — с похожими видами;
- расстояние (0.20): до ближайшей её очной встречи; без точки — совпадение города;
- надёжность (0.15): `h/(h+5)`, «Организация месяца» +0.2;
- активность (0.15): `1 − e^(−n/3)` по встречам в ближайший месяц;
- для новичка (0.10, только у новичков): доля встреч «Любой» / «Для новичков».
Где я был 3+ раза — `× 0.5`: этот клуб уже «свой».

## API
| Метод | operationId | Что |
|---|---|---|
| `GET /api/recommendations/events?lat&lon&radiusKm&sportId&from&to&page&size` | `recommendations_events` | `PageResponse<RecommendedEventResponse>`: карточка ленты + `score`, `distanceKm`, `reasons`, `discovery` |
| `GET /api/recommendations/events/{id}/explain?lat&lon` | `recommendations_explain` | все признаки (значение, вес, вклад), множители, `eligible` и `excludedReason` |
| `POST /api/recommendations/events/{id}/dismiss` `{reason}` | `recommendations_dismiss` | 204; `NOT_INTERESTED`, `NOT_MY_SPORT` (ещё и штраф виду), `TOO_FAR`, `BAD_TIME` |
| `DELETE /api/recommendations/events/{id}/dismiss` | `recommendations_undismiss` | 204, идемпотентно |
| `GET /api/recommendations/organizations?lat&lon&limit` | `recommendations_organizations` | `RecommendedOrganizationResponse[]` |
| `PUT /api/users/me/preferences` | `users_saveMyPreferences` | + необязательная `home: {lat, lon}`; не передана — очищается |

Коды причин (`RecommendationReasonCode`) — для иконок; текст `text` показывается как есть.

## Как подкрутить
Веса и параметры — `app.recommendations.*` в `application.yml` (`RecommendationProperties`): `weights.*`,
`half-life-days`, `horizon-days`, `discovery-every` (0 — без слотов), `mmr-lambda`, `max-distance-factor`,
`max-candidates`. Сумма весов не обязана быть 1. Проверять удобно через `explain` у Анны на демо.

## Демо
У Анны (новичок, бег и йога, серия баскетбола с Сергеем и Дмитрием) и Ольги (зарядка, утро) задан дом.
Анна уже скрыла турнир «Ладьи» — `explain` у него показывает «Вы скрыли его из подборки».

## Ограничения
- Считается на каждый запрос по всей базе: на демо-объёме это десятки миллисекунд; на десятках тысяч пользователей
  понадобится кэш «популяции» (похожести видов и организаторов) с обновлением раз в несколько минут.
- Посещение не подтверждается (как в истории посещений): «был» = подтверждённая запись или отметка на прошедшем занятии.
- Пояс разового мероприятия определяется по ближайшему из ~15 крупных городов России.
- Веса подобраны вручную, а не обучены: для обучения (например, логистической регрессии по «записался / скрыл»)
  нужно больше реальных данных.
