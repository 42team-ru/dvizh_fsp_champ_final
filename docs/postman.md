# Postman: проверка сценариев приёмки

Коллекция `postman/acceptance.postman_collection.json` проходит сценарии приёмки через API и проверяет ответы: статусы, тексты ошибок, блок `viewer`. Это быстрая проверка, что задеплоенный или локальный бэк живой и правила работают. UI она не заменяет.

## Запуск

Нужен бэк с `DEMO_MODE=true`: вход админа берётся из демо-данных.

```bash
docker compose up --build          # или make dev + make back
make postman                       # http://localhost:8080
make postman URL=https://<домен>   # проверить стенд
```

`make postman` запускает [newman](https://github.com/postmanlabs/newman) через `npx`, ставить ничего не нужно (только Node). Итог: таблица в конце, `failed` должно быть 0.

В Postman: Import → `postman/acceptance.postman_collection.json` → на коллекции «…» → Run → Run. Окружение не обязательно: значения по умолчанию (`baseUrl = http://localhost:8080` и логины) лежат в переменных коллекции (вкладка Variables), окружение `local.postman_environment.json` их только переопределяет. Имена переменных чувствительны к регистру: `{{baseUrl}}`, не `{{baseurl}}`. Запускать **всю коллекцию по порядку**: папки используют пользователей и мероприятия, созданные выше. Отдельную папку можно гонять, только если перед ней уже прошли «0. Подготовка» и «1. Создание события».

Каждый прогон создаёт новых пользователей с уникальным суффиксом, поэтому коллекцию можно гонять сколько угодно раз на одной базе. Мусор после прогонов (`pm_*` пользователи, мероприятия «… Postman …») останется в базе: на демо-стенде перед показом лучше `docker compose down -v`.

## Что проверяется

| Папка | Сценарий | Что внутри |
|---|---|---|
| 0. Подготовка | — | бэк отвечает, демо-режим включён, без входа 401 |
| 1. Создание события | 1 | справочник видов спорта; событие из справочника и со своим видом (`custom`, пробелы схлопнуты); 400 без адреса; другой пользователь находит в ленте (`searchText`, `joinMode`) и открывает карточку |
| 2. Допуск организации | 2 | без анкеты 404; до одобрения публиковать нельзя (403); анкета → PENDING; не админ в админке 403; админ не создаёт события; отказ с причиной → организация видит причину → правка → снова PENDING → одобрение; публикация без модерации с `organizationId`; публичная страница и событие видны пользователю; события на странице организации (`?organizationId=`) и организация в карточке события |
| 3. Свободная запись | 3 | сразу CONFIRMED, «вы записаны», приватные детали открылись; повтор 409; «Мест нет» 409; организатор видит участника и не может записаться сам; отмена и повторная запись |
| 4. Запись по заявке | 4 | PENDING и «ждёт решения»; чужие заявки видит только организатор (403); принять одну, отклонить другую с причиной; оба видят итог; отклонённый не может подать заново |
| 5. Уточнение условий | 5 | незаписанный задаёт вопрос; пустой — 400; организатор отвечает с меткой «Организатор»; порядок и авторство в обсуждении; `viewer.canComment` |
| 6. Снятие с публикации | 6 | дашборд; поиск в админке; снятие без причины — 400; снятие и удаление с причиной; удалённое снять нельзя (409); фильтр по статусу; оба пропали из ленты; по ссылке — статус и причина, запись 409, у удалённого обсуждение закрыто; в «Моих записях» видно, что произошло |
| 7. Сессия | — | me → refresh → logout → 401 |

Покрыты все шесть сценариев на уровне API. Интерфейс коллекция не проверяет.

## Переменные окружения

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `baseUrl` | `http://localhost:8080` | адрес бэка |
| `password` | `Postman#Pass1` | пароль пользователей, которых создаёт прогон |
| `adminUsername` | `admin` | демо-админ |
| `demoPassword` | `demo-password-1` | пароль демо-аккаунтов (`DEMO_PASSWORD`) |

Авторизация идёт через cookie `access_token`: Postman и newman хранят её сами, и каждый запрос «Вход: …» переключает текущего пользователя.
