# Postman: проверка сценариев через API

Коллекция `postman/acceptance.postman_collection.json` проходит шесть сценариев приёмки через API и
проверяет статусы, тексты ошибок и блок `viewer`. Это быстрая проверка, что локальный или задеплоенный
бэкенд жив и правила работают. Интерфейс она не проверяет.

```bash
make postman                       # http://localhost:8080
make postman URL=https://<домен>   # стенд
```

Нужен бэкенд с `DEMO_MODE=true` — вход админа берётся из демо. `make postman` запускает newman через
`npx`, ставить ничего не нужно. В итоговой таблице `failed` должно быть 0.

В Postman: Import → коллекция → «…» → Run. Запускать всю коллекцию по порядку: папки используют
пользователей и мероприятия, созданные выше. Каждый прогон создаёт новых пользователей с уникальным
суффиксом, поэтому коллекцию можно гонять на одной базе сколько угодно. Мусор (`pm_*`, мероприятия
«… Postman …») остаётся — перед показом лучше пересоздать базу.

| Папка                  | Что проверяется                                                                                                                       |
|------------------------|---------------------------------------------------------------------------------------------------------------------------------------|
| 0. Подготовка          | бэкенд отвечает, демо включено, без входа — 401                                                                                       |
| 1. Создание события    | вид из справочника и свой (`custom`, пробелы схлопнуты); 400 без адреса; другой пользователь находит и открывает                      |
| 2. Допуск организации  | без анкеты 404; до одобрения 403; отказ с причиной → правка → снова на проверке → одобрение; публикация без модерации; страница клуба |
| 3. Свободная запись    | сразу `CONFIRMED` и приватные детали; повтор и «Мест нет» — 409; организатор видит участника и не может записаться сам                |
| 4. Запись по заявке    | `PENDING`; чужие заявки — 403; принять одну, отклонить другую с причиной; оба видят итог                                              |
| 5. Уточнение условий   | вопрос от незаписанного; ответ организатора с цитатой и меткой; правка, удаление, ответ на удалённое — 409                            |
| 6. Снятие с публикации | без причины — 400; снятие и удаление с причиной; пропало из ленты; по ссылке — причина, запись 409                                    |
| 7. Бобр                | каталог, сохранение образа целиком и по слоту, неизвестная вещь — 400 без частичных изменений                                         |
| 8. Сессия              | me → refresh → logout → 401                                                                                                           |

| Переменная      | Дефолт                  | Что                              |
|-----------------|-------------------------|----------------------------------|
| `baseUrl`       | `http://localhost:8080` | адрес бэкенда                    |
| `password`      | `Postman#Pass1`         | пароль создаваемых пользователей |
| `adminUsername` | `admin`                 | демо-админ                       |
| `demoPassword`  | `demo-password-1`       | пароль демо-аккаунтов            |

Вход — через cookie `access_token`, Postman хранит её сам; каждый запрос «Вход: …» переключает текущего
пользователя.
